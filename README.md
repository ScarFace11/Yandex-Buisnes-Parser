# 🔍 Yandex Business Parser v2.2.1

Веб-приложение для автоматического парсинга бизнесов с Яндекс.Карт и 2ГИС.

---

## ✨ Что нового в v2.2.1

**2GIS как источник данных:**
- **Источник 2GIS** — официальный Catalog API (Places /3.0/items): соцсети, сайты и телефоны приходят прямо из ответа API. Один запрос ≈ 10 организаций, до 5 страниц на точку. Ключ берётся из `.env` (`TWOGIS_API_KEY`, бесплатный с [dev.2gis.ru](https://dev.2gis.ru)) или вводится в интерфейсе.
- **Ключ без контактов — не проблема**: если демо-ключ режет `contact_groups`, карточки фирм добираются через Chrome CDP автоматически.
- **Ключи Яндекса и 2GIS сохраняются одной кнопкой** «💾 Сохранить ключи в .env» — обе записи в один `.env` с мгновенной активацией без перезапуска.

**Фильтр по конкретным соцсетям (шаг «Соцсети и API»):**
- В режиме «С соцсетями» раскрывается сетка плиток соцсетей (VK, TG, WA, IG и др.). Отмеченные сети становятся **обязательными**: в результаты попадают только бизнесы, у которых найдены ВСЕ выбранные платформы. Фильтр работает и для Яндекса, и для 2GIS.
- Если в сырых данных обязательной соцсети не оказалось, детальная страница карточки загружается принудительно — данные не теряются.

**Интерфейс:**
- **Лог как терминал**: моноширинный шрифт, компактные строки, цветовая индикация (серый — системные, зелёный — успех, красный — ошибки), кнопка «🧹 Очистить лог».
- **Статистика всегда доступна** — дефолтные карточки с нулями видны до первого запуска; во время поиска цифры дозаполняются по мере завершения городов.
- Выровнены пары счётчиков в «Глубине поиска», укрупнены цифры в блоках статистики, кнопки «Повторить/Удалить» в истории стали заметнее, вкладки получили hover-эффект и активную тень.

## ✨ Что было нового в v2.2.0

**Скорость и надёжность парсинга:**
- **Быстрая загрузка карточек через Chrome (CDP)** — Yandex отдавал пустые страницы «анти-бот» для встроенного HeadlessChrome. Теперь карточки грузятся за **2–6 сек** вместо 60–340 сек через httpx-фолбэк. Город на ~200 компаний — **~5–15 мин** вместо 1,5–2 часов.
- **Жёсткий таймаут httpx** — страница, которая «капает» байтами, больше не занимает 200–300 сек: общий дедлайн 60 сек на запрос.
- **Retry через CDP при анти-бот заглушке** — вместо молчаливой потери данных идёт повторная загрузка на свежей вкладке.
- **Быстрая остановка и пропуск города** — Stop/⏭ срабатывает за **1–3 сек**: CDP-навигация, семафоры и очереди прерываются мгновенно, а процесс сохраняет чекпоинт и Excel перед завершением (graceful stop).
- **Исправлен `rps_drop`** — раньше снижение RPS было no-op (в логах: `rps_drop: 10 RPS` ничего не делало).
- **Исправлен фильтр госучреждений** — сопоставление по основам слов: «больниц», «поликлиник», «госпитал».

**Новые функции веб-интерфейса:**
- **Живая статистика** — общая по всем городам и **по каждому городу отдельно**: соцсети (разбивка по платформам), рейтинги, категории, время поиска, пропущенные города.
- **Живая таблица результатов** — строки появляются в реальном времени, пока идёт поиск.
- **Статистика обновляется после каждого завершённого города** — ещё до конца всего запуска (с зелёным бейджем на вкладке).
- **История поиска в списке городов** — под городом в выпадающем списке видно дату последнего поиска и ключевые слова (до 3 + «+N», полный список в тултипе).
- **Кнопка «Очистить историю»** — сбрасывает историю и подписи городов.
- **Фильтры качества данных** — «Объединять филиалы сетей» (схлопывает дубли по имени+телефону) и «Только с телефоном или соцсетями» (убирает пустые записи).
- **Возобновление прерванного поиска (чекпоинт)** — продолжение с места остановки; исправлен баг, из-за которого ключ чекпоинта содержал timestamp и resume не находил сохранённый прогресс.
- **Сброс интерфейса при новом запуске** — прогресс городов, счётчики и статистика не «липнут» от предыдущего запуска.

**Прочее:**
- Результаты сохраняются в `_results_for_frontend.json` после **каждого города** — при жёстком падении/остановке таблица и статистика не пустые.
- Ротация логов: чистка при каждом запуске, максимум 200 файлов / 30 дней.
- 99 автотестов (CDP-таймауты, фильтры вывода, rate-limit, stop/skip-реактивность).

## 🚀 Установка

### Быстрая установка

```bash
git clone https://github.com/ScarFace11/Yandex-Buisnes-Parser.git
cd Yandex-Buisnes-Parser

# Создание виртуального окружения
python -m venv .venv

# Активация (Windows)
.venv\Scripts\activate

# Активация (Linux/macOS)
source .venv/bin/activate

# Установка зависимостей
pip install -r requirements.txt

# Запуск
python app.py
```

Откройте браузер: **http://localhost:5000**

> 💡 Если используете Python 3.14, где Playwright падает с 0xC0000005 — парсер автоматически переключится на CDP-клиент (Chrome DevTools Protocol).

### API-ключи

Ключи Яндекса и 2GIS вводятся прямо в веб-интерфейсе — секция **02 · Соцсети и API**:
1. Вставьте ключ в поле «API-ключ Яндекса» и/или «API-ключ 2GIS»
2. Нажмите **💾 Сохранить ключи в .env** — оба ключа запишутся в `.env` и заработают сразу

Или создайте файл `.env` вручную (шаблон — `.env.example`):
```
YANDEX_API_KEY="ваш_ключ_сюда"
TWOGIS_API_KEY="ключ_с_dev.2gis.ru"
```

> 🔑 Ключ Яндекса: [Yandex Cloud Developer](https://developer.tech.yandex.ru/) · Ключ 2GIS: [dev.2gis.ru](https://dev.2gis.ru) → Platform Manager → создать ключ с разрешением Places API

## 🏙 Multi-city поиск

В поле «Где ищем?» можно указать несколько городов:

1. Начните вводить название — появится выпадающий список
2. Выберите город кликом или Enter
3. Добавьте следующий город
4. Нажмите «Найти компании»

**Как работает:**
- Города обрабатываются последовательно (общий пул вкладок Chrome)
- Под городом в списке видна дата последнего поиска и ключевые слова
- После каждого завершённого города статистика обновляется сразу (бейдж на вкладке)
- Каждый город — отдельный Excel-файл
- Кнопка **⏭ Город** — пропустить текущий город (быстро, ~1–3 сек)
- Кнопка **⏹ Стоп** — сохраняет чекпоинт и частичные результаты

## 📦 Сборка в .exe (Windows)

Проект собирается в один исполняемый файл через PyInstaller — локально или автоматически в GitHub Actions.

**Автоматически (рекомендуется):** запушьте тег `v*` (например `git tag v2.2.1 && git push origin v2.2.1`) — workflow `.github/workflows/build-exe.yml` прогонит тесты, соберёт exe, проверит его смоук-тестом и приложит `YandexBusinessParser-windows-x64.zip` к GitHub Release.

**Локально:**
```bat
build.bat
```

Результат: `dist\YandexBusinessParser\YandexBusinessParser.exe` (портативная папка; можно заархивировать и переносить). Запуск → откройте `http://127.0.0.1:5000`.

Особенности сборки:
- `output/`, `logs/`, `.env`, `sender_config.json` создаются **рядом с exe** (см. `paths.py`) — данные сохраняются между запусками;
- **авто-обновление из exe**: при выходе новой версии в приложении появляется баннер «⬆ Обновить сейчас» — скачивает релиз с GitHub и перезапускается сам, вручную ничего скачивать не нужно (бэкап старой версии остаётся в `_update/_backup/`);
- Playwright исключён из сборки (~300 МБ): парсер использует Chrome CDP (нужен установленный Chrome) или httpx-фолбэк;
- при первом запуске Windows SmartScreen может предупредить о неподписанном файле — «Подробнее → Выполнить в любом случае».
