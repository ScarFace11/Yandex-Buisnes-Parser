# Changelog

Все заметные изменения проекта. Формат — по версиям, свежие сверху.
Версия текущей сборки видна в шапке приложения (`config.APP_VERSION`).

## [2.3.0] — Массовый обход соцсетей, UI-фиксы, macOS-сборка

Итог релиза: macOS-сборка (`.app`/`.dmg`, с подписью Developer ID или ad-hoc),
массовый обход профилей, переработанный журнал «Ход поиска», мягкие темы на
общих токенах и большой батч багфиксов таблицы, паузы и статистики.

### 🤖 Релизный конвейер: черновик из CHANGELOG

- При пуше тега `v*` job **release-draft** (build-exe.yml) вырезает секцию
  версии из `CHANGELOG.md` (`scripts/release_notes.py`), создаёт **черновик
  релиза** с заголовком « vX — Подзаголовок» и этим телом ещё до сборки exe.
- Windows-джоба только прикрепляет `.zip` к готовому черновику,
  macOS-джоба — `.zip`/`.dmg`; авто-заметки из коммитов больше не затирают
  тело. Пока релиз — черновик, пользователи его не видят: публикуется одной
  кнопкой, когда оба билда зелёные.
- Если секции для версии в CHANGELOG нет — тело собирается из ссылки на
  CHANGELOG и списка коммитов с прошлого тега (нужен `fetch-depth: 0`).
- Существующий релиз не перезаписывается; шаг проверки ждёт exe на релизе и
  честно сообщает состояние (`draft` / `published`).

### 🔴 Последний батч багфиксов

- **Счётчик токенов 2GIS сбрасывается при смене ключа** — новый ключ = новая
  месячная квота. Если ключ не изменился, счётчик не трогается; в логе —
  «🔄 Новый ключ 2GIS — счётчик токенов сброшен».
- **Полоски/сферы городов в автодополнении приглушены** (`hsl(hue, 38%, 55%)`
  вместо 65%/42%) — цвета больше не «выедают глаза», контраст с фоном сохранён.
- **Пауза доведена до конца:** кнопка честно показывает «⏳ Пауза (завершаем
  город…)», поиск дожидается конца текущего города, а «▶ Продолжить» стартует
  **со следующего города** (оставшийся список городов передаётся при
  возобновлении; недобранный город дособирается через seen-cache).
- **KPI «Через taplink» и «С рейтингом» удалены** из статистики — бесполезные
  метрики (вторая ещё и не считалась). Остались «Всего найдено», «С соцсетями»,
  «Время».
- **«🔧 Технические детали» работают:** техстроки (API-запросы, координаты,
  HTTP-коды, трейсы) хранятся скрытыми, тоггл показывает их; фильтр
  «Технические» видит их независимо от состояния тоггла.
- **Уведомление о лимите 2GIS появляется один раз**, а не в каждом городе:
  лимит останавливает весь прогон, данные сохраняются, в финале —
  «Собрано до города X включительно».
- **Фильтр «Важные» расширен:** скрывает также «── Запрос …: начало поиска»,
  пагинацию, HTTP-коды и служебные трейсы; остаются города, источники,
  находки, файлы и ошибки.
- **«Время» в статистике фиксируется после завершения** (`_runEnd`), а не
  продолжает тикать при переключении вкладок; новый запуск сбрасывает таймер.

### 🍎 Сборка для macOS: .app, .dmg и свой каталог данных

- **Новый билд — `.app`-бандл**: `parser-mac.spec` + `./build-mac.sh`
  (публичная сборка) и `./build-mac.sh --dev` (сборка разработчика). Готовый
  бандл перетаскивается в `/Applications` и запускается двойным кликом.
- **Автоматически в CI**: `.github/workflows/build-macos.yml` собирает две
  архитектуры (`arm64` на `macos-15` и `x64` на `macos-15-intel` — образ
  `macos-13` снят с поддержки), подписывает, прогоняет смоук-тест бандла
  (реальный запуск + HTTP 200) и упаковывает в `.zip` (`ditto`) и `.dmg`; на
  теге `v*` файлы доливаются в тот же GitHub Release, где лежит Windows-архив.
- **Подпись Developer ID и нотаризация**: если в секретах репозитория задан
  `MACOS_CERTIFICATE_P12` (+ пароль и Apple ID для нотаризации), бандл
  подписывается Developer ID с hardened runtime и `entitlements.plist`,
  отправляется в Apple (`notarytool`) и получает тикет (`stapler`) —
  Gatekeeper запускает приложение без предупреждений. Без секретов — ad-hoc
  подпись и `::warning::` в логе CI, сборка не падает. Тот же режим доступен
  локально: `YP_CODESIGN_IDENTITY="Developer ID Application: …" ./build-mac.sh`.
- **Данные больше не пишутся внутрь бандла**: на macOS `paths.py` уводит
  `output/`, `logs/`, `.env` в `~/Library/Application Support/YandexBusinessParser`
  (у dev-сборки — своя папка `…ParserDev`), потому что `.app` из `/Applications`
  может быть только для чтения. Windows-поведение не изменилось: данные рядом с exe.
- **Приложение само открывает браузер** — у `.app` нет консоли с адресом
  (отключается `YP_OPEN_BROWSER=0`); Windows-сборка по-прежнему показывает консоль.
- **Порт на macOS — 5050** (на macOS 12+ порт 5000 занят системным AirPlay
  Receiver — приложение просто не могло запуститься). Занятый порт вообще
  перестал быть фатальным: берётся следующий свободный и пишется в лог, так что
  две копии приложения больше не конфликтуют (касается и Windows).
- **Выход попадает в `app.log`**, если у процесса нет stdout (оконный режим
  PyInstaller оставляет `sys.stdout = None`) — иначе трейсбеки при сбое
  уходили бы в никуда.
- **Авто-обновление изнутри приложения на macOS не предлагается**: подменить
  запущенный бандл нельзя, поэтому `/update/status` отдаёт `auto_apply: false`,
  `/update/download` и `/update/apply` объясняют причину, а в баннере вместо
  «Обновить сейчас» — кнопка «Скачать vX ↗» со страницей релизов. Версия всё
  равно проверяется, так что про новый релиз приложение сообщит.
- По умолчанию сборка подписана ad-hoc: в README (раздел «Как настроить
  подпись macOS») и в выводе `build-mac.sh` есть готовый шаг
  `xattr -dr com.apple.quarantine …` для первого запуска.

### 🤖 Автоматизация GitHub

- **`ci.yml`** — то, чего не хватало: тесты шли только внутри сборок по тегу
  и ветке `dev`, поэтому обычный PR не проверялся вообще. Теперь на каждый PR
  (и push в `main`/`dev`) pytest + node-тесты UI идут на **трёх** системах
  (Ubuntu, Windows, macOS), плюс проверка, что оба `.spec`-файла парсятся и все
  workflow-YAML валидны.
- **`dependabot.yml`** — раз в неделю PR на обновление pip-зависимостей
  (мелкие и патчевые — одним групповым PR) и версий GitHub Actions; мажоры
  PyInstaller игнорируются: они ломают spec'и и требуют ручной проверки.

### 🔴 Массовый обход соцсетей: открываются все вкладки

- **Открывалось 1 окно вместо N.** `window.open` после `await` теряет
  user-activation, и браузер отдавал только первую вкладку. Теперь пустые
  вкладки открываются **синхронно в обработчике клика**, а URL-ы из ответа
  сервера подставляются в них следом. Лишние пустые вкладки закрываются, если
  очередь кончилась раньше.
- **Блокировка больше не молчит.** Если попап-блокировщик съел часть вкладок,
  показывается «Открыто X из N. Разрешите всплывающие окна» и предлагается
  fallback «📋 Скопировать ссылки».
- **Кнопка «Открыть N профилей» больше не выключается** после первого клика.
  Она активна, пока есть непросмотренные, и всегда показывает актуальное число:
  «Открыть 5 профилей» → после батча «Открыть 3 профиля» → «✅ Все просмотрены».
  Понятие «цель сессии» и текст «по 5 за клик» убраны — за один клик
  открывается ровно то, что написано на кнопке (до 50).

### 🔴 Оценка лида: подсказка объясняет именно вашу компанию

- Вместо общей формулы тултип показывает **сработавшие критерии** этой записи
  (`✅ Нет сайта +30`, `✅ Рейтинг 4.7 +15`), промахи (`❌ Телефон — не указан`)
  и итог «Итого: N (макс. 90)».
- Если сохранённая в файле оценка расходится с текущими данными (например,
  ВК-активность проверяли в другой день), подсказка прямо об этом пишет вместо
  того, чтобы показывать неверную сумму.
- Разбор считается на клиенте по зеркалу `lead_score.py`; тесты сверяют баллы,
  пороги (4.5 / 50) и список дорогих категорий с Python-оригиналом, чтобы
  подсказка и колонка не разъехались.

### 🔴 Отметки «Просмотрено» сохраняются сами

- Отметки записываются в xlsx **автоматически**: через 5 секунд после последнего
  клика, при переключении на «Историю файлов», перед экспортом и при закрытии
  вкладки (через `sendBeacon`).
- Новый индикатор: «⏳ Есть несохранённые отметки» → «✅ Все отметки сохранены»,
  ошибка записи видна как «⚠ Отметки не записаны».
- Кнопка «💾 Отметки в файлы» переименована в **«💾 Сохранить сейчас»** и
  остаётся для ручной записи.
- `/reviewed/persist` принимает тело в формате beacon (`text/plain`), поэтому
  запрос при закрытии вкладки больше не теряется.

### 🟡 Таблица: «#» больше не сортируется

- Колонка «#» — порядковый номер строки, а не поле данных. У неё убраны
  обработчик клика, стрелки сортировки, hover и курсор-указатель; мёртвая ветка
  сортировки по индексу удалена.

### 🟡 Убрана кнопка «⊘ Дубли»

- Дублировала «Объединять филиалы сетей» из аккордеона «Фильтрация результата».
  Кнопка, её обработчик и стили удалены; объединение филиалов осталось на месте
  (аккордеон + правило объединения).

### 🟡 Мягкая тёмная тема

- Палитра переведена на **токены** (`--bg`, `--card`, `--panel`, `--field`,
  `--bdr`, `--txt`, `--sub`, `--muted`, `--hdr`, `--row-hover`, `--ok-*`,
  `--warn-*`, `--err-*`, `--glow*`) — вместо ~230 хардкод-hex.
- Фон — тёмно-синий графит вместо почти чёрного, текст — мягкий светло-серый
  вместо чисто белого, акцент — приглушённая бирюза вместо «ядовитой».
  Контраст ключевых элементов ≥ 4.5:1 (текст таблицы ≈ 17:1, подписи ≈ 5.4:1,
  шапка таблицы ≈ 11.9:1).
- Шапка таблицы в тёмной теме стала тёмной (белый текст на светлой бирюзе не
  читался).
- **Тема применяется до первой отрисовки** (мини-скрипт в `<head>`), поэтому при
  загрузке больше нет вспышки светлой темы; переключение — с коротким плавным
  переходом 0.22 с (уважает `prefers-reduced-motion`).
- **Светлая тема переведена на тот же набор токенов.** Раньше обе темы частично
  жили на своих hex-ах; теперь правила читают `var(--…)`, а отличаются только
  значения в `:root` и `[data-theme="dark"]`. Тест проверяет, что наборы токенов
  совпадают, что вне блоков токенов нет hex-литералов и что контраст всех пар
  «текст на фоне» ≥ 4.5:1 в **обеих** темах.
- **⏸ Пауза — оранжевая** в обеих темах (градиент `--pause-from`/`--pause-to`,
  тёмный текст на нём держит контраст); красный остался только за ⏹ «Остановить».
- **Состояние паузы видно и после перезагрузки страницы:** `/status` отдаёт
  `paused`, и кнопка снова предлагает «▶ Продолжить», а не начинает новый поиск.
  Простановки в логе при паузе честные («Поставлен на паузу — прогресс сохранён»)
  вместо «Остановлено пользователем».

### 🔵 Журнал «Ход поиска»: структура вместо debug-консоли

- **Фильтры в шапке журнала:** [Все] · [Важные] · [Ошибки] · [Технические].
  «Важные» убирает механику (геокодинг, сырые координаты, «Запрос начат»,
  трейсы клиентов), «Ошибки» оставляет предупреждения и ошибки (на кнопке — их
  количество), «Технические» показывает только служебные строки. Скрытие —
  чистый CSS на контейнере, поэтому смена фильтра ничего не перерисовывает и
  ни одна строка не теряется. Если под фильтром пусто — прямо там написано,
  например «✅ Ошибок нет».
- **Цвет и вес по уровню:** ✅ успех — зелёный и жирный, 📡 инфо — бирюзовый,
  ⚠ предупреждение — оранжевый, `[!]`/🚨 — красный и жирный, внутренние трейсы —
  приглушённый серый. Уровень решает класс, текст — только запасной признак.
- **Иерархия:** строки конфигурации стоят с отступом под своей шапкой, а
  **блоки городов сворачиваются** кликом по заголовку «🏙 Город 1/2: …» —
  скрывается всё до следующего города, состояние блока сохраняется для строк,
  которые приходят после свёртки.
- **Метки времени стали тихими:** колонка слева сохраняет ширину, но текст
  показывается только при смене секунды — вместо пятидесяти «14:30:15» подряд.
  Точное время каждой строки осталось в подсказке при наведении.
- **Индикатор автоскролла:** журнал следит за последней строкой, пока вы не
  прокрутили вверх; тогда появляется плавающая кнопка **«⬇️ К последней
  строке»** со счётчиком новых строк, а чтение не «дёргается» вниз.
- **Кнопки [💾 Сохранить лог] и [📋 Копировать]:** выгрузка в `.log` с полными
  метками времени и копирование всего журнала в буфер обмена (с тостом об
  успехе или ошибке).
- **Прогресс-бар стал объяснимым:** текущий город крупно, «Осталось ≈ …»,
  и мини-полоски по городам — видно, какой город идёт и какой уже готов.
- **Счётчики получили контекст:** «Запросов к API: 43» и «Найдено записей: 50
  (из 43 запросов)» — цифра больше не висит без объяснения.
- **Пустой журнал** показывает подсказку, а не пустоту; журнал по-прежнему
  обрезается до 1200 строк, чтобы DOM не разрастался на длинных прогонах.

### 🐞 Исправления предыдущего батча (вошли в этот же релиз)

- Пауза действительно останавливает поиск, а продолжение стартует сразу
  (паузнутый запуск закрывается, продолжение не встаёт в очередь).
- Повторный запуск по уже спарсенному городу больше не даёт «0 городов» и пустой
  Excel — вместо этого понятное объяснение.
- Рейтинги и телефоны 2GIS читаются (`org_rating`/`general_rating` вместо
  несуществующих `rating`/`review_count`), добавлен разбор телефона из карточки.
- Дедупликация лога: «Поиск: N город(ов)», «Прочие запросы», пути файлов
  печатаются по одному разу; метки времени абсолютные (`[14:30:15]`).
- «Соцсети» как отдельная вкладка убраны: сбор соцсетей идёт всегда, проверка
  активности ВК живёт в фильтрах.
